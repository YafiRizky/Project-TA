## FRAMEWORK ALTERNATIF (Non-Laravel)

Karena Laravel terlalu mainstream di kampus, **pilihan framework yang bisa jadi pembeda:**

### OPSI 1: **FastAPI (Python)** - HIGHLY RECOMMENDED
**Kenapa?**
- Modern, fast, auto-generate API docs (Swagger)
- **Seamless ML integration** (Python native)
- Async support (performance bagus)
- Type hints (clean code)
- Mudah deploy ke cloud (Docker-friendly)

**Cocok untuk**: Semua 3 ide top (API-first approach)

**Kekurangan**: Frontend terpisah (harus pakai React/Vue)

---

### OPSI 2: **Django + Django REST Framework**
**Kenapa?**
- Python native (ML integration mudah)
- Admin panel auto-generate (rapid prototyping)
- ORM powerful
- Security built-in
- Mature ecosystem

**Cocok untuk**: Ide dengan banyak CRUD (POS, Recruitment)

**Kekurangan**: Lebih monolithic, learning curve medium

---

### OPSI 3: **Node.js + Express + TensorFlow.js**
**Kenapa?**
- JavaScript full-stack
- ML bisa di frontend (TensorFlow.js)
- Lightweight, flexible
- Banyak library modern

**Cocok untuk**: Real-time apps, interactive dashboards

**Kekurangan**: ML ecosystem kurang mature dibanding Python

---

### OPSI 4: **Flask (Python)** - Minimalis tapi Powerfull
**Kenapa?**
- Lightweight, flexible
- Python native (ML integration mudah)
- Easy learning curve
- Bisa build sesuai kebutuhan (micro-framework)

**Cocok untuk**: Semua ide, especially API-centric

**Kekurangan**: Harus setup banyak hal manual (auth, admin, dll)

- Weather data (optional, if API available)
- Price changes history

---

### B. ALGORITMA ML YANG DIIMPLEMENTASI

**1. ARIMA (AutoRegressive Integrated Moving Average)**
- **Use Case**: Prediksi univariate time series
- **Kelebihan**: Good for linear trends, established method
- **Kekurangan**: Tidak handle seasonal kompleks, butuh stationary data
- **Implementation**: `statsmodels.tsa.arima`

**2. Prophet (by Meta/Facebook)**
- **Use Case**: Time series dengan seasonality & holidays
- **Kelebihan**: Handle missing data, automatic seasonality detection, interpretable
- **Kekurangan**: Slower untuk real-time prediction
- **Implementation**: `fbprophet`

**3. XGBoost Regression**
- **Use Case**: Multivariate forecasting (pakai external features)
- **Kelebihan**: Handle non-linear patterns, feature importance, akurasi tinggi
- **Kekurangan**: Butuh feature engineering manual
- **Implementation**: `xgboost.XGBRegressor`

**4. LSTM (Long Short-Term Memory) - Optional Advanced**
- **Use Case**: Complex sequential patterns
- **Kelebihan**: Capture long-term dependencies
- **Kekurangan**: Butuh data banyak, training lama, resource intensive
- **Implementation**: `tensorflow.keras.layers.LSTM`

### D. EVALUATION METRICS

**Metrics yang Digunakan:**
```python
# Mean Absolute Percentage Error (primary metric)
MAPE = (1/n) * Σ(|actual - predicted| / actual) * 100

# Root Mean Squared Error
RMSE = sqrt(mean((actual - predicted)²))

# Mean Absolute Error
MAE = mean(|actual - predicted|)
```

**Target Performance:**
- MAPE < 20% (good)
- MAPE < 15% (excellent)
- RMSE minimal

**Comparison Table:**
```
Model         | MAPE  | RMSE  | Training Time | Inference Time
------------------------------------------------------------------
ARIMA         | 18.2% | 8.5   | 30s          | 0.1s
Prophet       | 15.7% | 7.2   | 2m           | 0.5s
XGBoost       | 14.3% | 6.8   | 5m           | 0.05s
LSTM          | 16.1% | 7.0   | 30m          | 0.2s

Best Model: XGBoost (lowest MAPE & RMSE)
```

```python
import pandas as pd
import numpy as np
from faker import Faker

fake = Faker()

# Define product categories
products = [
    {'name': 'Indomie Goreng', 'category': 'Food', 'base_demand': 8, 'price': 3500},
    {'name': 'Susu Ultra 1L', 'category': 'Beverage', 'base_demand': 5, 'price': 15000},
    # ... 50-100 products
]

# Generate transactions
transactions = []
for day in range(365):  # 1 year data
    date = start_date + timedelta(days=day)
    is_weekend = date.weekday() >= 5
    
    for product in products:
        # Add variability
        demand_factor = 1.3 if is_weekend else 1.0
        noise = np.random.normal(0, 0.2)
        daily_demand = product['base_demand'] * demand_factor * (1 + noise)
        
        # Seasonal pattern
        if product['category'] == 'Ice Cream':
            seasonal_factor = 1.5 if date.month in [11,12,1,2] else 0.8
            daily_demand *= seasonal_factor
        
        quantity = max(0, int(np.random.poisson(daily_demand)))
        
        transactions.append({
            'date': date,
            'product': product['name'],
            'quantity': quantity,
            'price': product['price'],
            'revenue': quantity * product['price']
        })

df = pd.DataFrame(transactions)
df.to_csv('synthetic_sales_data.csv', index=False)
```

**Karakteristik Data Realistic:**
- Seasonality (weekend lebih ramai, holiday spike)
- Product lifecycle (new product ramp up, declining products)
- Random noise (tidak perfect smooth)
- Promotion effects (spike during discount)
- Stockout simulation (zero sales karena out of stock)

**Kenapa Prophet?**

**Comparison:**

```
Implement:

Cukup 2 model! Show: "Prophet 15% lebih akurat dari Moving Average"
```

**Training Flow (Simple):**
```python
import pandas as pd
from fbprophet import Prophet

# 1. Load data
df = pd.read_csv('daily_sales.csv')
df.columns = ['ds', 'y']  # Prophet butuh format ini

# 2. Train model (1 line!)
model = Prophet()
model.fit(df)

# 3. Predict
future = model.make_future_dataframe(periods=30)
forecast = model.predict(future)

# 4. Save model
model.serialize('model.pkl')

# Done! Tidak perlu complex tuning untuk MVP.
```

```python
import pandas as pd
from fbprophet import Prophet

# 1. AMBIL DATA dari database
query = """
    SELECT date, qty_sold 
    FROM daily_sales 
    WHERE product_id = 1  -- Indomie Goreng
    ORDER BY date
"""
df = pd.read_sql(query, connection)

# Data jadi kayak gini:
# date       | qty_sold
# -----------+----------
# 2025-02-01 | 45
# 2025-02-02 | 52
# ...
# 2026-01-29 | 56

model = Prophet()
model.fit(df)

# ML sekarang bisa detect pattern:
```

```python
from fbprophet import Prophet

model = Prophet.load('models/indomie_model.pkl')

# 2. PREDICT 7 hari ke depan
future = model.make_future_dataframe(periods=7)
forecast = model.predict(future)

# 3. AMBIL HASIL PREDIKSI
prediction = forecast['yhat'].tail(7).sum()  # Total 7 hari ke depan
# Contoh result: 385 pcs

# 4. CEK STOK SEKARANG
current_stock = get_current_stock(product_id=1)  # 95 pcs

# 5. HITUNG REKOMENDASI
if prediction > current_stock:
    recommendation = "RESTOCK"
    order_qty = prediction - current_stock + 50  # +50 = safety stock
else:
    recommendation = "AMAN"
    order_qty = 0

# 6. RETURN RESULT
return {

    "current_stock": 95,
```

## Pertanyaan Balik:

1. **Mau pakai 2 role (simple) atau 3 role (proper)?**
   - 2 role = faster development
   - 3 role = more professional, tapi +1 minggu effort

2. **Apakah kasir boleh void transaksi sendiri?**
   - Yes = kasir bisa batalkan transaksi (butuh password approval)
   - No = harus minta Admin untuk void

3. **Apakah kasir bisa lihat profit per produk?**
   - Yes = kasir tahu margin (bisa jadi motivasi)
   - No = profit rahasia owner only (lebih common)

Jawab 3 pertanyaan ini, nanti saya finalize role & permission design yang pas untuk sistem kamu.
