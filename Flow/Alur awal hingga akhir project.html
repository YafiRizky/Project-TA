Gambaran Umum & Tech Stack

Apa itu POS ML System dan teknologi apa yang digunakan

Apa Ini?

POS ML System adalah aplikasi Point of Sale (Kasir) berbasis web untuk UMKM, khususnya warung kelontong kecil. Bedanya dengan POS biasa: sistem ini dilengkapi 5 modul Machine Learning yang membantu pemilik warung mengambil keputusan bisnis berdasarkan data, bukan perkiraan.

Ada 2 jenis user:

  • Admin/Owner — Pemilik warung. Bisa mengelola semua: produk, stok, laporan, ML, kasir, diskon, pembayaran.
  • Kasir — Pegawai kasir. Hanya bisa melakukan transaksi POS, melihat riwayat, stock opname, dan profil sendiri.

Tech Stack

Frontend

React 18 + Vite, TailwindCSS, React Query (TanStack), Recharts, React Icons, React Router v6

Backend

Django 6.0 + Django REST Framework, PostgreSQL, Simple JWT (Auth), django-auditlog

Machine Learning

scikit-learn (Ridge Regression, Linear Regression), pandas, numpy

Payment Gateway

Xendit API (QRIS, eWallet, Transfer Bank) — mode development/test

Arsitektur Multi-Tenant

Sistem mendukung multi-bisnis. Satu owner bisa memiliki beberapa toko/cabang. Semua data (produk, stok, transaksi, ML) terisolasi per bisnis menggunakan business_id di setiap query.

Owner punya owner_code unik (6 karakter) untuk mengidentifikasi kepemilikan. Kasir terikat ke satu bisnis via business_code.

Fase 2 — Setup Master Data (Admin/Owner)

Owner mengatur fondasi bisnis: kategori, supplier, produk, dan diskon

Cerita: Owner Setup Produk Warung

Setelah login, Yafi melihat Dashboard dengan widget ringkasan: total produk, total transaksi hari ini, stok rendah, revenue hari ini. Sidebar kiri berwarna slate-900 (gelap) dengan ikon dan section group.

1. Halaman Kategori (/categories) — Admin Only

3. Halaman Produk (/products) — Admin Only

Halaman ini lebih kompleks. Di atas ada 3 card summary: Total Produk, Produk Aktif, Stok Rendah. Di bawah ada tabel dengan kolom: Nama, Kode, Kategori, Harga Jual, Harga Beli, Unit, Min Stok, Status.

Fase 3 — Inventori & Stok Batch

Mengelola stok barang masuk, batch, dan stock opname

Cerita: Owner Terima Kiriman Barang

Setiap kali Yafi belanja stok di Indogrosir, dia mencatat barang masuk di halaman Stok Batch (/inventory). Halaman ini menampilkan semua batch yang pernah masuk, dengan filter: Status (ACTIVE / DEPLETED), Produk, dan tanggal.

Halaman Stok Batch (/inventory) — Admin Only

Di atas halaman ada 4 card summary: Total Batch Aktif, Total Nilai Stok, Batch Mendekati Expired, Batch Habis. Di bawah ada tabel batch dengan kolom: Kode Batch, Produk, Qty, Harga Beli, Tanggal Beli, Tanggal Expired, Status.

Tombol + Tambah Batch membuka modal form:

  • Produk (dropdown search) — pilih produk yang akan di-restock
  • Jumlah / Qty — berapa unit yang dibeli
  • Harga Beli per Unit — harga modal per unit
  • Tanggal Pembelian — kapan dibeli
  • Tanggal Expired (opsional) — untuk produk yang ada masa kadaluarsa

Setiap batch mendapat batch_code unik otomatis. Batch berstatus ACTIVE saat masih ada stok, dan otomatis berubah ke DEPLETED saat qty = 0 (habis terjual via FIFO).

Halaman Stock Opname (/stock-opname) — Admin & Kasir

Fitur ini untuk pencocokan stok fisik vs stok sistem. Kasir atau owner bisa buka halaman ini, pilih produk dan batch, lalu input jumlah stok fisik aktual. Sistem menghitung selisih (variance):

  • Selisih positif: stok fisik lebih banyak dari sistem (kelebihan)
  • Selisih negatif: stok fisik lebih sedikit dari sistem (kehilangan/rusak)

Admin bisa menyetujui atau menolak hasil opname. Jika disetujui, stok di sistem otomatis disesuaikan dan dicatat di audit log.

Fase 4 — POS Kasir & Transaksi

Inti dari sistem: proses jual beli di kasir

Cerita: Kasir Rina Melayani Pembeli

Kasir Rina login dengan business_code warung + username "Kasir Rina" + password. Sidebar-nya berwarna hijau emerald (beda dari admin yang biru). Dia hanya melihat 5 menu: Dashboard, Transaksi Baru, Riwayat Transaksi, Stock Opname, Profil.

Rina klik "Transaksi Baru" dan masuk ke halaman POS fullscreen.

Halaman POS (/pos) — Admin & Kasir

Ini adalah halaman paling kompleks di sistem (46KB). Layout dibagi 2 kolom:

  • Kolom Kiri (70%): Grid produk. Di atas ada search bar + filter kategori (tab horizontal). Setiap produk ditampilkan sebagai card: nama, harga, stok tersedia. Klik card untuk menambahkan ke keranjang.
  • Kolom Kanan (30%): Keranjang belanja. Daftar item yang dipilih: nama, qty (bisa + / -), harga per unit, subtotal. Di bawah ada: Total, Diskon (otomatis dari promo aktif atau manual), Grand Total.

Di bawah keranjang ada panel pembayaran:

  • Pilih Metode: CASH, QRIS, Transfer, E-Wallet (radio buttons)
  • Input "Uang Dibayar" (khusus CASH) — quick amount buttons: Rp 10rb, 20rb, 50rb, 100rb, Uang Pas
  • Tampilkan Kembalian otomatis dihitung
  • Tombol Checkout — hijau besar

Proses Checkout (Backend)

Saat kasir klik "Checkout", frontend mengirim POST /api/transactions/transactions/checkout/ dengan payload: daftar item (product_id, qty), metode bayar, jumlah dibayar, catatan diskon.

Backend melakukan:

  • Validasi stok — cek apakah produk ada stok yang cukup
  • Alokasi FIFO — kurangi stok dari batch terlama dulu
  • Hitung total — subtotal, diskon, grand total, kembalian
  • Generate kode transaksi — format: STRX-YYMMDD-0001
  • Simpan Transaction + TransactionItems
  • Update batch qty — jika habis, set status = DEPLETED

Setelah sukses, muncul popup struk/receipt dengan detail transaksi. Bisa dicetak (CSS print-friendly).

Fase 6 — Machine Learning (5 Modul AI)

Jantung dari project TA: prediksi dan rekomendasi cerdas

Halaman ML Predictions (/ml-predictions) — Admin Only

Halaman ini memiliki 5 tab horizontal di atas: Forecast Pendapatan, Klasifikasi Produk, Prediksi Stok Habis, Rekomendasi Restock, Risiko Expired. Setiap tab menampilkan data berbeda dari modul ML yang berbeda. Ada tombol Refresh untuk memperbarui prediksi.

Semua modul ML di-cache selama 5 menit di backend (Django cache) untuk performa. Data diisolasi per business_id.

Modul 1: Forecast Pendapatan (Tab 1)

Algoritma: Ridge Regression + Feature Engineering

Fitur input: day_of_week, is_weekend, is_payday (tgl 25-5), rolling_7d_avg (rata-rata revenue 7 hari terakhir)

Validasi: Train-Test Split 80/20 (shuffle=False untuk time series)

Metrik: R² (train & test), MAE (Mean Absolute Error), RMSE (Root Mean Squared Error)

UI menampilkan:

  • 4 card: Revenue Bulan Ini, Prediksi Bulan Depan (+ badge % pertumbuhan), Rata-rata Harian, Akurasi Model R²
  • 3 card validasi: MAE, RMSE, Train/Test Split (misal: 67/17)
  • Trend badge: "Tren NAIK/TURUN/STABIL" dengan penjelasan fitur yang digunakan
  • Grafik ComposedChart: Area (revenue aktual 30 hari) + Line dashed (prediksi 14 hari ke depan)

Modul 2: Klasifikasi Produk ABC (Tab 2)

Algoritma: Pareto Analysis (80/20 Rule)

Cara kerja: Urutkan produk berdasarkan total revenue, hitung persentase kumulatif. Kelas A = 0-80% kumulatif, Kelas B = 80-95%, Kelas C = 95-100%.

V2 Improvement:

  • Tambah analisis Profit (revenue - cost)
  • Tambah Trend 30 hari: bandingkan revenue 30 hari terakhir vs 30 hari sebelumnya. Muncul sebagai arrow UP/DOWN/STABLE + persentase.

UI menampilkan:

  • 3 card warna: Kelas A (hijau, Fast Moving), Kelas B (amber, Medium), Kelas C (merah, Slow/Dead)
  • Pie Chart: Distribusi jumlah produk per kelas
  • Bar Chart horizontal: Top 10 produk by revenue (warna sesuai kelas)
  • Tabel detail: #, Produk, Revenue, Profit, Qty, % Revenue, Kelas (badge), Trend 30d (arrow + %)

Modul 3: Prediksi Stok Habis (Tab 3)

Algoritma: Moving Average (7 hari & 30 hari)

Cara kerja: Hitung rata-rata penjualan harian per produk (7d dan 30d). Pakai yang tertinggi (lebih konservatif). days_until_stockout = current_stock / avg_daily_sales.

V2 Improvement:

  • Fixed N+1 query: satu query aggregated untuk semua stok
  • Tambah Standard Deviation penjualan harian
  • Tambah Confidence Level: HIGH (20+ hari data), MEDIUM (10+), LOW (3+), INSUFFICIENT_DATA

UI menampilkan:

  • Alert banner merah jika ada produk CRITICAL/HIGH
  • 4 card: Kritis (≤3 hari), Tinggi (≤7 hari), Sedang (≤14 hari), Aman (>14 hari)
  • Tabel: Produk, Stok, Avg/Hari 7d, Avg/Hari 30d, Habis Dalam (hari), Risiko (badge warna), Confidence (badge)

Modul 4: Rekomendasi Restock (Tab 4)

Algoritma:

  • Safety Stock = Z * sigma * sqrt(Lead Time), Z = 1.65 (95% service level)
  • Reorder Point = (avg_daily * lead_time) + safety_stock
  • EOQ (Economic Order Quantity) = sqrt((2 * Demand * Ordering Cost) / Holding Cost)

Kapan tampil: Hanya produk yang current_stock ≤ reorder_point yang ditampilkan sebagai "Perlu Restock".

UI menampilkan:

  • 3 card: Produk Perlu Restock, Total Estimasi Biaya, Lead Time
  • Tabel: Produk, Stok, Avg/Hari, Reorder Point, Qty Beli (rekomendasi), Est. Biaya, Urgensi (URGENT/SOON/OK)
  • Jika semua aman, muncul ikon centang hijau "Semua stok aman!"

Modul 5: Risiko Expired (Tab 5)

Algoritma: Deterministik + Sales Velocity

Cara kerja: Scan semua batch yang punya tanggal expired. Hitung hari tersisa. Hitung sales velocity (rata-rata penjualan harian 30 hari). Proyeksikan berapa yang bisa terjual sebelum expired.

V2 Improvement:

  • Projected Unsold: qty yang kemungkinan tidak terjual sebelum expired
  • Adjusted Loss: kerugian berdasarkan projected unsold (bukan full loss)
  • Rekomendasi Aksi: "Diskon 50% segera atau bundle", "Monitor, prioritaskan di display", dll

UI menampilkan:

  • 4 card: Sudah Expired (merah), Kritis ≤7 hari (oranye), Warning ≤30 hari (amber), Total Risiko Finansial (ungu)
  • Tabel per section (Expired, Kritis, Warning): Produk + Batch Code, Qty, Proyeksi Tdk Terjual, Est. Rugi, Expired kapan, Rekomendasi aksi

Fase 7 — Pengaturan & Multi-Bisnis

Fitur administratif: kelola kasir, pembayaran, profil, dan cabang

Halaman Kelola Kasir (/users) — Admin Only

Owner bisa menambah, mengedit, dan menonaktifkan kasir. Tombol + Tambah Kasir membuka modal: Username, Nama Lengkap, Password. Kasir yang dibuat otomatis terikat ke bisnis yang sedang aktif. Ada toggle untuk aktifkan/nonaktifkan kasir.

Halaman Pengaturan Pembayaran (/payment-settings) — Admin Only

Mengelola metode pembayaran yang tersedia di POS: CASH, QRIS, Transfer Bank, E-Wallet. Owner bisa mengaktifkan/menonaktifkan metode tertentu. Integrasi Xendit API disiapkan untuk pembayaran digital (mode development).

Halaman Profil (/profile) — Admin & Kasir

User bisa melihat dan mengedit profil mereka: nama lengkap, email, upload foto profil (disimpan di Django media). Ada section Ubah Password (password lama, baru, konfirmasi). Juga menampilkan info bisnis, role, owner_code/business_code.

Halaman Pilih Bisnis (/businesses) — Admin Only

Untuk owner yang memiliki lebih dari 1 bisnis/cabang. Halaman ini menampilkan daftar semua bisnis yang dimiliki sebagai card. Klik card untuk beralih ke bisnis tersebut. Semua data (produk, stok, transaksi, ML) langsung berubah mengikuti bisnis yang dipilih.

Ada juga tombol + Tambah Bisnis Baru untuk membuat cabang baru.

Fitur Shift Summary (Kasir Logout)

Saat kasir klik tombol Logout di sidebar, sebelum benar-benar keluar, muncul popup "Ringkasan Shift Anda" yang menampilkan:

  • Total Transaksi hari ini
  • Total Omzet (revenue) hari ini
  • Total Item Terjual
  • Breakdown per metode bayar (CASH: 5x Rp xxx, QRIS: 2x Rp xxx, dst)

Kasir bisa review dulu, lalu klik "Lanjut Logout" atau "Kembali". Baru setelah itu muncul konfirmasi logout final.

Notifikasi Stok (TopBar)

Di TopBar (header atas), ada ikon lonceng dengan badge angka. Badge menunjukkan jumlah produk dengan stok rendah + batch mendekati expired. Klik lonceng membuka dropdown panel berisi daftar alert: "Stok Indomie Goreng rendah (sisa 3)", "Batch Telur expired dalam 5 hari".

Alur Data Lengkap (End-to-End)

Berikut adalah perjalanan data dari awal hingga menjadi insight ML:

  1. Owner register → Business + User created di PostgreSQL
  2. Owner setup master data → Categories, Suppliers, Products tersimpan
  3. Owner catat stok masuk → ProductBatch created (qty, harga beli, expiry date)
  4. Kasir proses transaksi → Transaction + TransactionItems created, Batch qty dikurangi FIFO
  5. Data terakumulasi → Ratusan transaksi terkumpul selama berminggu-minggu
  6. Owner buka ML Dashboard → Backend query data transaksi + stok
  7. ML Engine memproses → pandas DataFrame, scikit-learn model.fit(), model.predict()
  8. Hasil dikembalikan sebagai JSON → Frontend render sebagai chart, tabel, card, badge
  9. Owner mengambil keputusan → "Harus restock Indomie besok", "Beras paling laris, tetap stok banyak"
